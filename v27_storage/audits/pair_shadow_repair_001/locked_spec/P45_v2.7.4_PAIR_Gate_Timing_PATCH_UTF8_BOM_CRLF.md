# P45 v2.7.4 PAIR Gate Timing and Transaction PATCH

## 0. 공식 지위

- authority: `OFFICIAL_PAIR_GATE_TIMING_PATCH`
- project version: `P45 v2.7.4`
- activation: `ACTIVE`
- 범위: PG05·PG14 평가 시점, payload layer, atomic round transaction 순서
- 우선순위: 이 문서는 기존 v2.7.4 문서의 PG05·PG14 timing/transaction 문구와 충돌할 때 그 부분에만 우선한다.
- 불변: gate predicate/threshold, state precedence, 50/200, risk/recent/structure/bonus, Pareto, ranking, SET1/SET2, outcome, PRIMARY/SUPPORT, PAIR→CORE는 변경하지 않는다.

## 1. 공식 불변 원칙

1. PG01~PG14와 final pre-result PAIR state는 R outcome 최초 접근 전에 확정한다.
2. R 입력 경계는 `source_end_round = R-1`이다.
3. payload layer는 PRELOCK, FINAL-PREDICTION, FINALIZATION으로 분리한다.
4. hash 참조는 앞 layer에서 뒤 layer로만 흐른다.
5. commit 결과는 gate/state 입력이 아니다.
6. commit 실패는 round 전체 rollback이며 COMPLETE와 exposure에 포함하지 않는다.

## 2. PRELOCK과 PG05

PRELOCK은 R-1 경계, 후보, rule signature, pre-result 원시 입력을 outcome 전에 잠그는 prediction integrity layer다.

canonical field는 다음으로 고정한다.

```text
prelock_version = PAIR-PRELOCK-1.0
evaluation_round
source_end_round
data_prefix_hash
candidate_bundle_hash
rule_signature_bundle_hash
pre_result_raw_input_bundle_hash
policy_linkage_hash
outcome_access_count_before_prelock
```

PG05·PG14 결과, final PAIR state, outcome, future data, commit 결과는 PRELOCK에 포함하지 않는다. 모든 bundle의 canonical 원문을 staging record와 함께 보존한다.

PG05는 PRELOCK을 active round transaction에 staging한 뒤, outcome loader 호출이 0인 상태에서 판정한다.

PASS 조건:

1. `source_end_round = evaluation_round - 1`
2. outcome 접근 count 0
3. 필수 PRELOCK field와 bundle 원문 존재
4. bundle canonical SHA-256 일치
5. PRELOCK canonical JSON 재계산 hash와 staged hash 일치
6. staged bytes 재파싱·canonical 재직렬화 결과 일치

필수 입력·record 누락은 INCOMPLETE, 값·hash·경계 불일치 또는 선행 outcome 접근은 FAIL이다. transaction commit과 outcome은 PG05 입력이 아니다.

## 3. FINAL-PREDICTION과 PG14

PG05 PASS 후 PG01~PG13을 공식 규칙대로 평가한다. FINAL-PREDICTION은 그 입력·결과와 PG14가 검증할 pre-result write-set을 잠근다.

canonical field는 다음으로 고정한다.

```text
write_set_version = PAIR-FINAL-PREDICTION-1.0
evaluation_round
source_end_round
prelock_hash
gate_pg01_pg13_bundle_hash
ranking_selection_bundle_hash
policy_linkage_hash
required_field_manifest_hash
schema_constraint_manifest_hash
audit_write_set_manifest_hash
outcome_access_count_before_final_prediction
```

PG14 결과, final PAIR state, outcome, future data, commit 결과는 FINAL-PREDICTION에 포함하지 않는다. 모든 bundle/manifest canonical 원문을 함께 staging한다.

PG14는 FINAL-PREDICTION payload/hash와 write-set을 staging한 뒤 outcome 접근 0 상태에서 판정한다.

PASS 조건:

1. PRELOCK link 일치와 PG05 PASS
2. PG01~PG13 공식 입력 및 결과 완전
3. ranking/representative context와 policy linkage 완전
4. 필수 normalized pre-result row, report payload/hash가 manifest에 존재
5. staged schema/FK/unique/check/hash 검증 PASS
6. outcome 접근 count 0
7. FINAL-PREDICTION canonical hash 재계산 일치

필수 입력·row·manifest 누락은 INCOMPLETE, 값·hash·schema·FK·constraint 불일치 또는 선행 outcome 접근은 FAIL이다. 실제 commit 성공 여부는 PG14 입력이 아니다.

## 4. FINALIZATION

PG14 확정 후 PG01~PG14 전체 vector와 공식 precedence로 final pre-result PAIR state를 확정한다.

canonical field는 다음으로 고정한다.

```text
finalization_version = PAIR-PREDICTION-FINALIZATION-1.0
evaluation_round
prelock_hash
final_prediction_hash
gate_pg01_pg14_vector_hash
state_precedence_policy_hash
final_pair_state
outcome_access_count_before_finalization
```

PG01~PG14 vector와 state 판정 원자료를 같이 보존한다. FINALIZATION은 PRELOCK과 FINAL-PREDICTION을 변경하지 않는다. outcome, future data, commit 결과를 포함하지 않는다.

## 5. 공식 transaction 순서

```text
BEGIN ROUND TRANSACTION
1. R과 R-1 경계 확정, outcome 접근 0 확인
2. 후보·pre-result 원시 입력·rule signature 계산
3. PRELOCK payload/hash와 audit 원문 staging·재검증
4. PG05 확정
5. PG01~PG13 공식 평가
6. FINAL-PREDICTION payload/hash와 write-set staging·재검증
7. PG14 확정
8. PG01~PG14와 precedence로 final pre-result PAIR state 확정
9. FINALIZATION staging·재검증
10. outcome 접근 0 재확인
11. R outcome 최초 조회
12. outcome 저장
13. round COMPLETE staging
14. COMMIT
```

COMMIT 성공은 `ROUND_TRANSACTION_CERTIFIED` 실행 인증이다. 실패 시 전체 rollback하며 gate/state를 사후 변경하지 않는다. resume은 동일 R-1 prefix에서 세 payload와 hash를 재계산하며 결과가 하나라도 다르면 결정론 위반으로 fail-fast한다.

## 6. 비순환 hash 방향

```text
R-1 raw inputs
→ PRELOCK/hash
→ PG05
→ PG01~PG13
→ FINAL-PREDICTION/hash
→ PG14
→ final state
→ FINALIZATION/hash
→ outcome
→ commit certification
```

- PG05 자기참조: 0
- PG14 자기참조: 0
- final state 자기참조: 0
- outcome/commit의 gate-state 입력 경로: 0
