# P45 v2.7.4 PAIR PG13 Sequence PATCH

## 0. 공식 지위

- authority: `OFFICIAL_PAIR_PG13_SEQUENCE_PATCH`
- activation: `ACTIVE`
- project version: `P45 v2.7.4`
- 우선순위: PG13 lifecycle과 PG13/PG14 실행·확정 순서에 한해 기존 Gate Amendment와 Gate Timing PATCH의 충돌 문구를 보완한다.
- 불변: PG13·PG14 연구 목적, PG01~PG12, threshold, state precedence, 50/200, ranking, risk/recent/structure, outcome

## 1. 공식 gate identity 순서

```text
PG01,PG02,PG03,PG04,PG05,PG06,PG07,
PG08,PG09,PG10,PG11,PG12,PG13,PG14
```

PG13은 하나의 gate identity와 하나의 최종 PASS/FAIL/INCOMPLETE 결과를 갖는다. 내부 lifecycle만 PRELIMINARY와 FINAL_CERTIFICATION으로 분리한다. FINAL_CERTIFICATION은 새 gate나 PG13 재실행이 아니다.

## 2. PG13 PRELIMINARY

PG01~PG12가 공식 순서로 실행·잠긴 뒤 13번째 gate identity로 PG13을 activation한다.

required input:

```text
actual_trace_prefix=[PG01..PG12]
locked_pg01_pg12_record_hash
official_gate_sequence_descriptor_hash
pg14_next_step_contract_hash
required_pre_result_input_manifest_hash
outcome_access_count_before_pg13_preliminary
```

actual trace prefix·locked hash·공식 sequence·PG14 deterministic next-step contract·필수 input manifest가 모두 일치하고 outcome 접근 count가 0이면 `PG13_PENDING_FINAL`로 잠근다. 필수 input 누락은 preliminary INCOMPLETE, 값/hash/trace 불일치나 outcome 선행 접근은 preliminary FAIL이다.

`PG13_PENDING_FINAL`은 PG13 내부 lifecycle marker다. PAIR gate result와 PAIR state가 아니며 final gate vector나 precedence 입력에 사용할 수 없다.

## 3. PG14

PG13 preliminary가 잠긴 뒤 PG14를 14번째 gate identity로 실행한다. 공식 Gate Timing PATCH의 FINAL-PREDICTION staging 및 schema/FK/unique/check/hash/필수-field 검증으로 PG14를 PASS/FAIL/INCOMPLETE로 확정한다.

PG14는 PG13 preliminary hash와 next-step contract link만 사용하며 PG13 final result를 입력으로 요구하지 않는다.

## 4. PG13 FINAL_CERTIFICATION

PG14 record가 잠긴 뒤 outcome 조회 전에 같은 PG13 record를 final certification한다.

required input:

```text
pg13_preliminary_record_hash
immutable_execution_trace=[PG01..PG12,PG13_PRELIMINARY,PG14]
locked_pg01_pg12_record_hash
locked_pg14_record_hash
official_gate_sequence_descriptor_hash
timing_patch_metadata_hash
outcome_access_count_before_pg13_final
```

PG13 PASS는 다음을 모두 만족할 때다.

1. preliminary marker가 `PG13_PENDING_FINAL`
2. preliminary record hash 일치
3. immutable trace 정확히 `[PG01..PG12,PG13_PRELIMINARY,PG14]`
4. locked PG01~PG12 및 PG14 record hash link 일치
5. trace gate identity projection 정확히 `[PG01..PG14]`
6. hidden gate identity count 0
7. official sequence/timing metadata hash 일치
8. outcome 접근 count 0

필수 input 누락은 PG13 INCOMPLETE, 값/hash/trace 불일치나 outcome 선행 접근은 PG13 FAIL이다. planned sequence만으로 PASS하지 않는다.

## 5. Final state와 outcome 경계

```text
PG01..PG12 final
→ PG13 PRELIMINARY / PENDING_FINAL
→ PG14 final
→ PG13 FINAL_CERTIFICATION / final
→ PG01..PG14 final vector
→ final pre-result PAIR state
→ FINALIZATION
→ outcome 최초 접근
```

모든 최종 gate와 PAIR state는 outcome 전에 확정한다.

## 6. 비순환 hash 방향

```text
PG01..PG12 record hash
→ PG13 preliminary hash
→ PG14 record hash
→ PG13 final certification hash
→ final gate vector/state/FINALIZATION
→ outcome
```

PG13 preliminary는 PG14/PG13 final을 참조하지 않는다. PG14는 PG13 final을 참조하지 않는다. PG13 final만 locked PG14 record를 참조한다. outcome/future data는 lifecycle 입력이 아니다.

## 7. Rollback/resume

commit 실패는 round 전체 rollback이다. resume은 동일 R-1 prefix에서 PG01~PG12, PG13 preliminary, PG14, PG13 final과 hash를 재계산한다. 동일 input에서 trace나 PG13 final 결과가 다르면 결정론 위반으로 fail-fast한다.
