## 1. Canonical JSON 공통 규칙

1. object key는 Unicode code point 오름차순이다.
2. 배열은 각 descriptor에 명시된 순서를 유지한다.
3. UTF-8, 공백 없음, NFC 문자열을 사용한다.
4. integer는 부호 있는 10진 JSON integer다.
5. rate와 percentile은 유한 JSON number이며 NaN/Infinity를 금지한다.
6. 값이 공식적으로 산출 불가능하면 해당 fixed field에 JSON `null`을 넣는다. key 생략과 임의 key 추가를 금지한다.
7. SHA-256 입력은 canonical UTF-8 JSON bytes다.
8. 코드 위치·파일명·주석·formatting은 semantic descriptor에 넣지 않는다.

## 2. Rule identity와 Context 분리

`pair_rule_signature`는 반복 가능한 selection rule만 식별한다. round, number identity, constituent identity/state/signature, UNIT 값, role/evidence, risk/recent/structure/bonus 값, outcome, future data는 제외한다.

`pair_context_fingerprint`는 R outcome 최초 접근 전에 존재하는 해당 candidate의 전체 동적 context를 식별한다. 동적 context가 바뀌어도 rule signature는 바뀌지 않는다. selection 동작을 규정하는 semantic policy가 바뀌면 해당 policy hash와 rule signature가 바뀐다.

## 7. Exact Context schema

### 7.1 representation

Context payload는 object가 아니라 fixed-order field record 배열을 사용한다.

```json
{"fields":[{"field_id":"<registry-id>","value":null}],"version":"PAIR-CONTEXT-FINGERPRINT-1.0-DRAFT"}
```

`fields`에는 아래 registry 21개 항목을 index 순서대로 정확히 한 번씩 저장한다. 생략·중복·unknown field를 금지한다. 복합 value는 지정된 fixed record type만 사용한다.
