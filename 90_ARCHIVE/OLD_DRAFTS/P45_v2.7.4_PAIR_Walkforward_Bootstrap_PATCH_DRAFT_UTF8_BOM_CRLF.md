# P45 v2.7.4 PAIR Walkforward Bootstrap PATCH DRAFT

- authority: NONE

- target: P45 v2.7.4 PAIR Gate Amendment
- purpose: pair_rule_signature와 signature별 과거 exposure 사이의 순환 의존성 제거

# 1. 발견된 순환

현재 공식 `pair_rule_signature` payload에는 pair rule risk, final PAIR structure, recent support, bonus dependence가 포함된다. 이 네 값은 동일 signature의 과거 selection exposure로 계산되므로 signature를 알아야 과거 exposure를 찾을 수 있고, 과거 exposure를 찾아야 signature를 만들 수 있다. 최초 등장과 context 변경 시 이 순환을 끊는 공식 규칙이 없다.

# 2. 제안하는 비순환 서명

`base_pair_rule_signature`를 결과 독립적인 selection-rule lookup key로 정의한다. 직렬화와 SHA-256 방식은 v2.7.4 제6.3항을 그대로 쓴다.

payload 포함 항목:

1. pair pool type
2. 두 constituent TRIO state 정렬 vector
3. 두 `trio_rule_signature` 정렬 vector
4. 다섯 UNIT별 pair coverage relation vector
5. role diversity vector
6. evidence overlap vector
7. member TRIO maximum opposite risk
8. member TRIO structure summary

7·8은 R 이전에 TRIO 단계에서 독립적으로 확정된 member 정보다. PAIR 자신의 selection exposure를 사용하지 않는다.

payload 제외 항목:

- pair rule opposite risk
- final PAIR structure
- PAIR recent support state
- PAIR bonus dependence
- outcome·rate·Wilson·p-value
- 숫자 identity·canonical pair key
- R 실제 결과와 미래자료
- rank와 최종 state

PAIR 과거성과에서 파생되는 제외 항목은 `base_pair_rule_signature`를 변경하지 않고 gate/state/ranking 입력으로만 저장한다. 기존 공식 signature payload를 바꾸므로 공식 채택 시 signature version을 새 값으로 올려야 한다. DRAFT 권장값은 `PAIR-RULE-SIGNATURE-1.1`이다.

# 3. 결정론적 bootstrap 순서

각 평가회차 R에서 다음 순서를 고정한다.

1. 1..R-1 자료만 읽는다.
2. UNIT→NUMBER→TRIO를 실행하고 valid TRIO를 확정한다.
3. 모든 disjoint PAIR의 구조 context와 member TRIO 정보를 계산한다.
4. `base_pair_rule_signature`를 결과 조회 전에 생성한다.
5. `(walkforward_run_id, base_pair_rule_signature, evaluation_round < R, COMPLETE selection exposure)`만 과거 조회한다.
6. 조회 exposure로 PRIMARY와 SUPPORT를 분리 집계하고 risk/recent/structure/bonus를 계산한다.
7. gate/state/Pareto/공식 15-key ranking을 계산한다.
8. 같은 R·base signature에서 rank가 가장 높은 대표 PAIR 최대 1개를 고른다. 완전 동률은 canonical pair key ASC다.
9. 모든 identity exposure와 대표 selection exposure, prediction context/hash를 원자적으로 결과 조회 전에 저장한다.
10. transaction의 prediction 저장이 확인된 뒤에만 R 결과를 읽는다.
11. integrated/main hit 원자료와 bonus-assisted flags 및 상호배타 category를 저장하고 round를 COMPLETE로 commit한다.

# 4. 최초·부족 표본 처리

## 4.1 최초 eligible 및 exposure 0

동일 base signature의 과거 selection exposure가 0이면 sample band `<50`을 그대로 적용한다. PRIMARY·SUPPORT evidence는 `INSUFFICIENT`, recent와 pair rule structure는 `INSUFFICIENT_SAMPLE` flag를 갖는다. outcome 성공·실패를 0회 표본의 0률로 주장하지 않는다.

pair rule risk는 존재하는 공식 원자료만 적용한다. member maximum risk와 current pair UNIT conflict는 계산 가능하다. PAIR 성과 조건은 evidence가 `INSUFFICIENT`이므로 HIGH/INFERIOR로 간주하지 않는다. 이는 임의 초기값이 아니라 공식 evidence 상태다. final structure는 member 실제 상태를 보존하고 pair rule `INSUFFICIENT_SAMPLE` flag를 별도로 둔다.

## 4.2 exposure 1..49

sample band `<50`, `PAIR_RESEARCH_HOLD`를 적용한다. 통계 원자료는 저장하지만 READY/TEST_READY 성과 관문에는 사용하지 않는다. 구조 비교 종점 50 미만은 `INSUFFICIENT_SAMPLE`이다.

## 4.3 exposure 50..199

공식 band대로 최대 `PAIR_TEST_READY`다. READY 승격은 금지한다.

## 4.4 exposure 200 이상

공식 통계·gate를 그대로 평가한다. 표본 수를 결과에 맞춰 변경하지 않는다.

# 5. signature 최초 등장과 변경

- base payload가 처음 등장하면 해당 signature exposure는 0에서 시작한다.
- 구성요소 하나라도 바뀌면 SHA-256이 달라지고 새 signature로 취급한다.
- 이전 signature exposure를 새 signature에 합치거나 이전하지 않는다.
- 구성요소가 다시 과거 값으로 돌아와 같은 base signature가 재현되면, R보다 작은 동일 signature COMPLETE selection exposure만 이어 사용한다.
- pair identity가 달라도 base signature가 같으면 같은 selection-rule 표본군에 속한다. 단 한 회차에서 대표는 최대 1개다.

# 6. identity와 selection exposure

모든 생성 PAIR는 `(run_id,R,canonical_pair_key)` identity exposure로 한 번 저장한다. 공식 성과 분모에는 identity exposure를 사용하지 않는다. selection exposure는 `(run_id,R,base_pair_rule_signature)`당 대표 한 개만 저장한다. 두 장부는 합산하지 않는다.

# 7. 자기참조·미래누출 차단

- R의 risk/recent/structure/bonus 계산 쿼리는 반드시 `evaluation_round < R AND round_status=COMPLETE`다.
- R outcome은 R prediction hash commit 이후에만 조회한다.
- R outcome은 R+1 이후 조회에만 포함된다.
- pair-derived metric은 base signature payload에 역입력하지 않는다.
- 결과 확인 후 base signature, 대표 identity, rank, SET 배정을 변경하지 않는다.

# 8. resume 재현

resume cache key는 draw prefix, UNIT/NUMBER/TRIO/PAIR rule hash, code hash, candidate rule hash, schema version, 공식 문서 hash set을 포함한다. 동일 cache key와 run_id에서 COMPLETE round는 다시 계산하지 않는다. 미완료 round는 transaction rollback 후 동일 1..R-1 prefix와 동일 base payload로 재계산하며 prediction hash가 기존 staged 값과 다르면 `FAILED_FATAL`이다.

# 9. schema274 보완

`pair_walkforward_outcome`에 다음 NOT NULL boolean 저장열을 둔다.

- `a_bonus_assisted_triple INTEGER CHECK IN (0,1)`
- `b_bonus_assisted_triple INTEGER CHECK IN (0,1)`

PRIMARY와 SUPPORT 및 MAIN/BONUS_ASSISTED 원자료를 분리 보존한다.

# 10. 공식 변경 범위

변경되는 부분은 v2.7.4 제6장의 signature payload와 version뿐이다. PAIR outcome taxonomy, baseline, sample band, risk 공식, structure 6지표, recent 규칙, gate, state precedence, Pareto, 15-key ranking은 완화하거나 변경하지 않는다.
