# P45 v2.7.4 PAIR PG13 Sequence PATCH DRAFT

## 0. 지위와 범위

- status: `DRAFT_ONLY / NOT_OFFICIAL`
- project version: `P45 v2.7.4`
- 연결 authority: 공식 PAIR Gate Amendment와 공식 Gate Timing PATCH
- 변경 범위: PG13 evaluation lifecycle, PG13/PG14 실행·확정 순서
- 변경하지 않음: PG13·PG14 연구 목적, predicate 목적, PG01~PG12, threshold, state precedence, 50/200, ranking, risk/recent/structure, outcome

## 1. Gate 실행 identity

공식 gate activation 순서는 정확히 다음 14개다.

```text
PG01, PG02, PG03, PG04, PG05, PG06, PG07,
PG08, PG09, PG10, PG11, PG12, PG13, PG14
```

PG13은 하나의 gate identity와 하나의 최종 결과만 갖되 내부 lifecycle을 `PRELIMINARY`와 `FINAL_CERTIFICATION`으로 분리한다. FINAL_CERTIFICATION은 새 gate activation이나 PG13 재실행이 아니다.

## 2. PG13 PRELIMINARY

PG01~PG12가 공식 순서로 실행·잠긴 직후 13번째 gate identity로 PG13을 activation한다.

required input:

```text
actual_trace_prefix = [PG01,PG02,...,PG12]
locked_pg01_pg12_record_hash
official_gate_sequence_descriptor_hash
pg14_next_step_contract_hash
required_pre_result_input_manifest_hash
outcome_access_count_before_pg13_preliminary
```

PRELIMINARY 조건:

1. actual trace prefix가 PG01~PG12와 정확히 일치
2. PG01~PG12 locked record hash 일치
3. official sequence descriptor가 PG13 다음 PG14를 요구
4. PG14 deterministic next-step contract가 존재하고 hash가 일치
5. 필수 pre-result 입력 manifest 완전
6. outcome 접근 count 0

필수 input이 없으면 preliminary status는 INCOMPLETE, 값/hash/trace가 다르거나 outcome이 이미 접근됐으면 FAIL이다. 모두 만족하면 `PG13_PENDING_FINAL`로 잠근다.

`PG13_PENDING_FINAL`은 PG13 내부 lifecycle marker이며 PAIR gate result나 PAIR state가 아니다. final gate vector와 precedence 입력에 사용할 수 없다.

## 3. PG14

PG13 preliminary record가 `PG13_PENDING_FINAL`로 잠긴 뒤 PG14를 14번째 gate identity로 실행한다. 공식 Gate Timing PATCH에 따라 FINAL-PREDICTION staging 및 schema/FK/unique/check/hash/필수-field 검증 후 PG14를 PASS/FAIL/INCOMPLETE로 확정한다.

PG14는 PG13 final result를 입력으로 요구하지 않는다. PG13 preliminary record hash와 official next-step contract link만 사용한다.

## 4. PG13 FINAL_CERTIFICATION

PG14 결과가 pre-result record로 잠긴 뒤 outcome 조회 전에 PG13의 동일 record를 final certification한다.

required input:

```text
pg13_preliminary_record_hash
immutable_execution_trace = [PG01,...,PG12,PG13_PRELIMINARY,PG14]
locked_pg01_pg12_record_hash
locked_pg14_record_hash
official_gate_sequence_descriptor_hash
timing_patch_metadata_hash
outcome_access_count_before_pg13_final
```

최종 PASS 조건:

1. preliminary marker가 `PG13_PENDING_FINAL`
2. preliminary record hash 일치
3. immutable execution trace가 정확히 `[PG01..PG12, PG13_PRELIMINARY, PG14]`
4. locked PG01~PG12와 PG14 record hash가 trace link와 일치
5. trace의 gate identity projection이 정확히 `[PG01..PG14]`
6. hidden gate identity count 0
7. official sequence/timing metadata hash 일치
8. outcome 접근 count 0

필수 input 누락은 PG13 INCOMPLETE다. 값/hash/trace 불일치 또는 outcome 선행 접근은 PG13 FAIL이다. 모두 만족하면 PG13 PASS다.

FINAL_CERTIFICATION은 PG13 predicate의 “실제 executed sequence 인증”을 완결하는 단계이며 planned sequence만으로 PASS하지 않는다.

## 5. Final gate vector와 state

PG13 final과 PG14 final이 모두 확정된 뒤에만 PG01~PG14 fixed-order vector를 만든다. 그 다음 공식 precedence로 final pre-result PAIR state를 확정하고 FINALIZATION을 검증한다. 이 모든 과정에서 outcome 접근 count는 0이어야 한다.

```text
PG01..PG12 final
→ PG13 PRELIMINARY / PENDING_FINAL
→ PG14 final
→ PG13 FINAL_CERTIFICATION / final
→ PG01..PG14 final vector
→ final pre-result PAIR state
→ FINALIZATION
→ outcome 최초 접근
```

## 6. Hash 방향과 비순환성

```text
PG01..PG12 record hash
→ PG13 preliminary hash
→ PG14 record hash
→ PG13 final certification hash
→ final gate vector hash
→ final state / FINALIZATION
→ outcome
```

- PG13 preliminary는 PG14 결과 또는 PG13 final을 참조하지 않는다.
- PG14는 PG13 preliminary link만 참조하고 PG13 final을 참조하지 않는다.
- PG13 final은 locked PG14 record를 참조하지만 PG14 record는 PG13 final을 참조하지 않는다.
- outcome과 future data는 어느 lifecycle input에도 포함하지 않는다.

## 7. Rollback/resume

commit 실패 시 round 전체를 rollback한다. resume은 동일 R-1 prefix에서 PG01~PG12 records, PG13 preliminary, PG14, PG13 final certification과 모든 hash를 재계산한다. 동일 input에서 trace와 PG13 final result가 다르면 결정론 위반으로 fail-fast한다.

## 8. DRAFT 판정 조건

sequence 의미 검증 10개가 모두 PASS할 때만 동일 의미의 공식 PATCH로 승격한다.
