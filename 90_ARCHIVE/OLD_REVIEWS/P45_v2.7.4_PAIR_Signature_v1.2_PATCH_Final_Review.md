## 2. 현재 DRAFT canonical rule payload

```json
{
  "baseline_policy": "P45-v2.7.4-EXACT-PAIR-BASELINES",
  "member_order_policy": "CANONICAL-LOWER-UPPER",
  "pair_pool_type": "EXPANDED_TEST_POOL",
  "representative_policy": "OFFICIAL-15-KEY-THEN-CANONICAL-PAIR-KEY",
  "sample_band_policy": "PAIR-INHERITS-TRIO-50-200",
  "selection_rule_authority": "P45-v2.7.4-PAIR",
  "signature_version": "PAIR-RULE-SIGNATURE-1.2-DRAFT"
}
```

이 payload의 counterfactual hash는 포함된 7개 필드를 각각 바꾸면 모두 달라졌다. 그러나 다음 실제 rule 설정은 payload에 직접 결속되지 않는다.

- eligibility policy hash
- valid_for_pair policy hash
- disjoint candidate generation policy hash
- official 15-key ranking policy hash
- representative-per-round-per-signature grouping policy hash
- PG01~PG14/state authority hash
- Bootstrap PATCH authority hash

이 설정을 실제로 변경하고 문자열 별칭을 그대로 두면 rule signature가 같아진다. 이는 under-separation이다.

## 6. Auditability

판정: `FAIL FOR OFFICIAL ADOPTION`

DRAFT는 rule/context payload 원문 저장을 요구하므로 방향은 PASS다. 그러나 다음이 공식 canonical schema로 완전히 고정되지 않았다.

- rule payload 안의 개별 official policy authority hash
- exact eligibility/candidate/ranking/grouping policy keys
- context payload의 정확한 key 목록·자료형·NULL 규칙·canonical 배열 순서
- policy hash 변경과 signature version 변경의 강제 관계

hash와 원문을 함께 저장한다는 원칙만으로는 under-separation을 막을 수 없다.

## 7. 필요한 최소 수정

전체 DRAFT를 다시 쓰지 말고 canonical rule payload 부분만 보완한다.

1. 다음 policy hash를 rule payload의 필수 키로 추가한다.
   - `candidate_generation_policy_hash`
   - `eligibility_policy_hash`
   - `valid_for_pair_policy_hash`
   - `disjoint_policy_hash`
   - `ranking_policy_hash`
   - `representative_grouping_policy_hash`
   - `gate_state_policy_hash`
   - `bootstrap_policy_hash`
   - `baseline_policy_hash`
   - `sample_band_policy_hash`
2. 각 hash의 공식 source document·section·canonical serialization을 명시한다.
3. hash 하나라도 달라지면 rule signature가 반드시 달라지도록 규정한다.
4. context payload의 정확한 canonical key/type/NULL/order 표를 추가한다.
5. rule policy hash는 별도 audit 열에만 두지 말고 rule signature payload 자체에 포함한다.

50/200 threshold와 기존 gate/state/risk/recent/structure/Pareto/ranking의 내용은 변경하지 않는다.
