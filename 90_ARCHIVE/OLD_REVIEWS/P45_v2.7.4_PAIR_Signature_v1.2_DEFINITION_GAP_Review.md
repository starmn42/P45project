## FAIL-FAST 결과

`GATE_DESCRIPTOR_GAP`

PG05와 PG14는 공식 원문만으로 prediction 시점 canonical gate descriptor를 하나로 확정할 수 없다.

### PG05 시간순서 충돌

- PG05 predicate: 모든 R 입력 end=R-1이고 prediction hash가 결과 read 전에 존재
- 공식 walkforward 순서: state와 Pareto 계산 → 15-key 사전 rank → prediction/hash 저장 → R outcome 복기

따라서 gate/state 계산 시점에는 아직 prediction hash 저장이 완료되지 않았다. PG05를 그 시점에 PASS, INCOMPLETE, staged 상태 중 무엇으로 기록할지 공식 규칙에 정의돼 있지 않다.

### PG14 시간순서 충돌

- PG14 predicate: 필수 normalized rows·report·hash 저장 완료 및 FK/integrity PASS
- 공식 부연: transaction commit 직전 staged 검증 후 commit 성공 시 최종 PASS
- 공식 walkforward 원칙: 회차 하나가 prediction과 outcome 복기를 포함하는 하나의 transaction

R outcome 전 canonical context fingerprint에 최종 PG14 상태를 넣으려면 outcome 전 commit이 필요하지만, 이는 회차 하나의 transaction 원칙과 충돌한다. staged 결과와 최종 PASS를 분리하는 공식 필드·상태도 정의돼 있지 않다.

## 영향

- PG01~PG14 canonical semantic descriptor: 미완성
- `gate_state_policy_hash`: 확정 불가
- gate/state가 포함된 exact context schema: 확정 불가
- gate/state counterfactual: 완전 검증 불가
- context auditability: 완전 PASS 판정 불가

공식 원문에 존재하는 15-key ranking 표 자체는 key 순서·방향·전역 NULL 정책을 제공하지만, 이번 요청은 gate 하나라도 공식 자료로 완성 불가능하면 중단하도록 명시했으므로 DRAFT에 부분 반영하지 않는다.

## 필요한 공식 보완

1. PG05 평가를 `prediction_prelock_planned`, `prediction_persisted_before_outcome`, 최종 gate 중 어느 시점·필드로 확정할지 정의
2. PG14의 staged 검증과 commit 후 최종 검증을 별도 상태로 저장할지 정의
3. 회차 원자 transaction과 outcome 전 prediction 영속화의 transaction 경계를 명확히 정의
4. context fingerprint가 pre-result staged gate를 담는지 최종 committed gate를 담는지 정의
