# P45 v2.7.4 PAIR Gate Timing Consistency Review

## 판정

`PAIR_GATE_TIMING_REVISION_REQUIRED`

## 확인된 충돌

### 1. PG05 평가 순서

제안 A의 PG05 순서는 다음과 같다.

```text
pre-result context/hash 생성
→ active transaction에 prediction record staging
→ staged payload 재검증
→ PG05 PASS
```

그러나 제안 B의 고정 transaction 순서는 다음과 같다.

```text
PG01~PG14 pre-result 평가
→ final pre-result PAIR state 확정
→ prediction context/hash staging 및 검증
```

PG05는 prediction staging 검증 뒤에만 PASS 가능한 동시에 모든 gate와 final state는 staging 전에 확정돼야 하므로 순환한다.

### 2. PG14 write-set 순서

PG14는 공식 pre-result gate/state/audit write-set이 완전하고 staging 검증을 통과해야 PASS다. 하지만 그 write-set에 PG14 결과와 final PAIR state가 포함되며 final state는 PG14 결과에 의존한다. provisional status, two-phase envelope 또는 fixpoint 직렬화 규칙이 공식적으로 정의되지 않은 상태에서는 하나의 canonical payload를 결정할 수 없다.

### 3. prediction hash와 context fingerprint

v1.2 DRAFT는 gate 결과와 final pre-result state를 canonical context payload에 포함한다. 따라서 최종 context fingerprint/prediction hash는 PG05·PG14 확정 뒤에만 계산할 수 있다. 반대로 두 gate는 해당 payload의 staging 검증을 요구하므로 현재 정의로는 비순환 계산 순서가 없다.

## 8개 Timing 검증

| 항목 | 판정 |
|---|---|
| PG05 outcome 전 판정 가능 | FAIL — staging과 gate/state 순서 순환 |
| PG14 outcome 전 판정 가능 | FAIL — final write-set 자기포함 |
| commit 결과 비의존 | PASS |
| final state outcome 전 확정 | 불명확 |
| commit 실패를 실행 무결성으로 분리 | PASS |
| prediction → gate/state → outcome 고정 | FAIL — transaction 고정 순서와 불일치 |
| rollback/resume 동일 state 재현 | 미검증 |
| outcome으로 gate/state 수정 경로 0 | PASS |

## 필요한 최소 공식 보완

다음 중 하나를 공식적으로 선택해야 한다.

1. `prelock_payload`와 `final_prediction_payload`를 분리하고 각각의 exact schema/hash 및 PG05·PG14 평가 단계를 정의
2. PG05·PG14를 gate/state payload 밖의 execution certification으로 완전히 분리하고 기존 gate ID 의미를 공식 개정
3. provisional gate vector를 허용하고 성공 시 final vector가 되는 결정론적 two-phase/fixpoint 직렬화 규칙 정의

선택 전에는 임의 구현·문서 보완을 금지한다.
