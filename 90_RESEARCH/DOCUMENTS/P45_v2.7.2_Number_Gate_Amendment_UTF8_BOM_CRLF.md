공식 버전: P45 Research Engine v2.7.2  
적용 범위: 6단계 번호 상태 판정과 후보군 압축  
인코딩: UTF-8 BOM  
줄바꿈: CRLF

# 0. 적용과 우선순위

P45 v2.7.2는 다음 문서의 결합으로 정의한다.

1. `P45_v2.7.1_Work_UTF8_BOM_CRLF.md`
2. 본 문서 `P45_v2.7.2_Number_Gate_Amendment_UTF8_BOM_CRLF.md`

NUMBER 상태·복귀 역할·후보군 압축 규칙이 충돌하면 본 문서가 우선한다.

v2.7.1의 다음 원칙은 그대로 유지한다.

- UNIT_3·UNIT_5·UNIT_9·UNIT_10·END_DIGIT 전부 필수
- 다섯 UNIT 결과의 점수 합산·가중 평균·다수결 금지
- 미래 데이터 차단
- 본번호·보너스·통합 성과 분리
- 3/3 주성과와 2/3 보조성과 분리
- 번호 6개를 먼저 확정하는 방식 금지
- 6단계는 번호 후보군까지만 생성
- TRIO·PAIR·세트1·세트2는 이후 단계
- 감사 결과가 CORE 잠금 결과를 변경하지 않음

# 1. 번호 수준 자료의 구성

각 번호 n은 다섯 UNIT의 번호별 문맥을 가진다.

```text
NUMBER_CONTEXTS(n)
= [
  UNIT_3 context,
  UNIT_5 context,
  UNIT_9 context,
  UNIT_10 context,
  END_DIGIT context
]
```

각 UNIT 문맥은 다음을 포함한다.

- UNIT 상태
- EXACT_VECTOR_CONTEXT
- LOCAL_GROUP_CONTEXT
- 전체·최근100·최근50·최근20
- 통합·본번호·보너스 표본과 적중률
- Wilson 95% 하한·상한
- 보너스 과의존
- 반대 가설 위험
- 구조 붕괴 상태
- 문맥 충돌
- 독립 근거 키
- 결정 해시

다섯 UNIT의 적중률을 평균내거나 합산하지 않는다.

---

# 2. 번호 대표 문맥 선정

## 2.1 평가 가능한 문맥

다음은 번호 대표 문맥 후보에서 제외한다.

- UNIT_SYSTEM_ERROR
- UNIT_NOT_APPLICABLE
- 필수 입력 누락
- 미래 데이터 누수
- 계산·저장·재조회 불일치
- NO_EVALUABLE_CONTEXT

UNIT_HOLD와 UNIT_FAIL 문맥은 대표 양성 문맥으로 선택하지 않지만,
충돌·반대·위험 판정에는 반드시 남긴다.

## 2.2 대표 문맥 선택 키

평가 가능한 문맥 중 다음 순서로 단 하나의
`primary_number_context`를 선택한다.

1. EXACT_VECTOR_CONTEXT 우선
2. 표본 상태: SUFFICIENT > BORDERLINE > INSUFFICIENT
3. 통합 전체 증거:
   POSITIVE_CONFIRMED >
   POSITIVE_TENTATIVE >
   NEUTRAL >
   NEGATIVE_TENTATIVE >
   NEGATIVE_CONFIRMED
4. 통합 전체 Wilson 하한이 높은 문맥
5. 본번호 전체 Wilson 하한이 높은 문맥
6. 최근100 표본 수준: OFFICIAL > BORDERLINE > REFERENCE
7. 최근100 통합 관측률이 높은 문맥
8. 최근50 표본 수준: OFFICIAL > BORDERLINE > REFERENCE
9. 최근50 통합 관측률이 높은 문맥
10. 그래도 같으면
    UNIT_3, UNIT_5, UNIT_9, UNIT_10, END_DIGIT 순

10번은 완전 동률 해소용 저장 순서일 뿐 UNIT 우선순위나 가중치가 아니다.

대표 문맥 외의 모든 문맥은 삭제하지 않고
`secondary_number_contexts`에 보존한다.

---

# 3. 번호 수준 위험의 보수적 결합

## 3.1 보너스 과의존

다섯 UNIT의 평가 가능한 번호 문맥 중 가장 높은 위험을 사용한다.

```text
NONE < MEDIUM < HIGH
number_bonus_dependence = max(unit_bonus_dependence)
```

## 3.2 반대 가설

```text
LOW < MEDIUM < HIGH
number_opposite_risk = max(unit_opposite_risk)
```

## 3.3 구조 붕괴

```text
NORMAL < CAUTION < WARNING < SEVERE
number_structure_state = max(unit_structure_state)
```

`INSUFFICIENT_SAMPLE`이 하나 이상 있으면 별도 플래그로 저장한다.
다른 UNIT의 실제 NORMAL·CAUTION·WARNING·SEVERE 결과를 지우지 않는다.

## 3.4 번호 문맥 충돌

- HIGH:
  하나 이상의 POSITIVE_CONFIRMED와
  하나 이상의 NEGATIVE_CONFIRMED가 동시에 존재
- MEDIUM:
  양성 문맥과 NEGATIVE_TENTATIVE가 동시에 존재
- NONE:
  위 조건에 해당하지 않음

위험 결합은 평균·점수·가중치가 아니다.
최악 상태를 보존하는 보수적 상한 규칙이다.

# 4. NUMBER 관문 입력값

NUMBER 관문 7~13과 17은
`primary_number_context`의 성과와
제3장의 번호 수준 위험을 함께 사용한다.

- 전체 표본: primary 전체 조건부 표본
- 통합 전체 적중률: primary 통합 전체 관측률
- 최근100 표본·적중률: primary 최근100
- 최근50 표본·적중률: primary 최근50
- 본번호 전체 적중률: primary 본번호 전체
- 보너스 과의존: number_bonus_dependence
- 반대 가설: number_opposite_risk
- 구조 붕괴: number_structure_state

대표 문맥을 선택한 사실과 선택 키 전체를 장부에 저장한다.

---

# 5. 파레토 규칙

번호 상태와 상대 순위를 분리한다.

- PARETO_NONDOMINATED:
  NUMBER_PASS 가능
- PARETO_DOMINATED:
  NUMBER_PASS 금지
  그러나 자동 NUMBER_FAIL 금지
- NOT_COMPARABLE:
  NUMBER_PASS 금지, 최대 NUMBER_TEST

기존 문구의 `동일 성과 우위`는 폐기한다.
상태 벡터가 완전히 같은 번호들은 모두 비지배로 남기고
제10장의 동점 순서로만 정렬한다.

---

# 6. NUMBER 상태 판정 우선순위

다음 순서를 고정한다.

```text
SYSTEM/DATA ERROR
→ NUMBER_FAIL
→ NUMBER_HOLD
→ NUMBER_PASS
→ NUMBER_WEAKEN
→ NUMBER_TEST
→ NUMBER_RETIRED
```

SYSTEM/DATA ERROR는 NUMBER 상태로 숨기지 않는다.
CORE_SYSTEM_HOLD 원인으로 기록한다.

---

# 7. NUMBER_FAIL

시스템 오류가 아니며 다음 중 하나면 NUMBER_FAIL이다.

1. UNIT_NO_SUPPORT
   AND primary 통합 전체가 NEGATIVE_CONFIRMED
2. primary 통합 전체가 NEGATIVE_CONFIRMED
   AND 양성 UNIT 지지가 없음
3. primary 본번호 전체가 NEGATIVE_CONFIRMED
   AND 통합 전체가 POSITIVE_CONFIRMED가 아님
4. number_opposite_risk = HIGH
   AND 하나 이상의 충분한 문맥이 NEGATIVE_CONFIRMED
5. number_structure_state = SEVERE
   AND primary 통합 전체가 NEGATIVE_CONFIRMED
6. 다섯 UNIT 중 평가 가능한 문맥이 모두
   NEGATIVE_CONFIRMED 또는 UNIT_FAIL

최근50·최근20의 무적중만으로 NUMBER_FAIL하지 않는다.
파레토 지배만으로 NUMBER_FAIL하지 않는다.

---

# 8. NUMBER_HOLD

FAIL·SYSTEM 오류는 아니지만 다음 중 하나면 NUMBER_HOLD다.

1. 대표 문맥을 만들 수 없음
2. UNIT_RELATION_INCOMPLETE가 계산 오류가 아닌
   임시 입력 불완전 상태로 명시됨
3. UNIT_NO_SUPPORT이지만 확정 음성은 아님
4. number_context_conflict = HIGH
5. number_opposite_risk = HIGH
6. number_bonus_dependence = HIGH
7. number_structure_state = SEVERE이고
   안정된 양성 근거가 없음
8. 전체와 최근100이 서로 반대 방향이며
   어느 쪽도 확정 우위가 없음
9. 필수 번호 수준 지표 일부가 판단 불가

HOLD는 계산 실패가 아니라
현재 조건에서 방향을 잠그지 못했다는 뜻이다.

---

# 9. NUMBER_PASS

다음 18개를 모두 만족해야 한다.

1. 미래 데이터 차단 완료
2. 다섯 필수 UNIT 계산 COMPLETE
3. 번호별 unit_state_vector 길이 5, 누락 없음
4. UNIT_RELATION_INCOMPLETE 아님
5. UNIT_NO_SUPPORT 아님
6. PARETO_NONDOMINATED
7. primary 전체 표본 30건 이상
8. primary 통합 전체 적중률 >= 7/45 + 0.015
9. primary 최근100 표본 15건 이상
   AND 통합 적중률 >= 7/45
10. primary 최근50 표본 8건 이상
    AND 통합 적중률 >= 7/45 - 0.02
11. primary 본번호 전체 적중률 >= 6/45
12. number_bonus_dependence = NONE
13. number_opposite_risk != HIGH
14. 데이터 누수·파싱·정규화 오류 0
15. 규칙·동점 순서 해시가 실행 전에 고정
16. 동일 입력 10회 결과 해시 동일
17. number_structure_state != SEVERE
18. 기대 관문 순서와 실행 관문 순서 일치,
    숨은 관문 0

추가 상한:

- number_context_conflict = HIGH이면 PASS 금지
- number_structure_state = WARNING이면 PASS 금지
- PARETO_DOMINATED 또는 NOT_COMPARABLE이면 PASS 금지

---

# 10. 강한 성과 통과의 정의

기존 문구 `전체·최근·본번호 관문을 강하게 통과`는
다음으로 고정한다.

```text
STRONG_PERFORMANCE_PASS
= NUMBER_PASS 관문 7~17을 모두 통과
  단, 관계·파레토·관문순서 항목 1~6·18은 제외
```

---

# 11. NUMBER_WEAKEN

FAIL·HOLD·PASS가 아니며 다음을 모두 만족해야 한다.

필수:

1. UNIT_RELATION_INCOMPLETE 아님
2. UNIT_NO_SUPPORT 아님
3. primary 전체 표본 20건 이상
4. primary 통합 전체가
   POSITIVE_CONFIRMED 또는 POSITIVE_TENTATIVE
5. primary 본번호 전체가 NEGATIVE_CONFIRMED가 아님
6. number_opposite_risk != HIGH
7. number_bonus_dependence != HIGH
8. number_context_conflict != HIGH

그리고 다음 중 하나:

- PASS 관문 중 최근·표본·본번호 조건 하나 이상이 경계
- UNIT_CONFLICT이지만 STRONG_PERFORMANCE_PASS
- number_opposite_risk = MEDIUM
- number_bonus_dependence = MEDIUM
- number_structure_state = WARNING
- PARETO_DOMINATED이지만 양성 방향이 유지
- 최근100이 중립·경계지만 확정 음성은 없음

WEAKEN은 양성 방향은 있으나 NUMBER_PASS로 잠그지 못한 상태다.

---

# 12. NUMBER_TEST

FAIL·HOLD·PASS·WEAKEN이 아니며 다음 중 하나면 NUMBER_TEST다.

1. primary 통합 전체가 NEUTRAL
2. primary 통합 전체가 NEGATIVE_TENTATIVE
3. primary 전체 표본이 20~29건
4. 최근100 표본이 8~14건
5. 최근50 표본이 5~7건
6. Wilson 구간이 무작위 기준을 포함
7. PARETO_NOT_COMPARABLE
8. 아직 실시간 누적 검증 중

## 12.1 유효 NUMBER_TEST

확장 후보군에 들어갈 수 있는 TEST는 다음을 모두 만족한다.

1. 시스템·데이터 오류 없음
2. UNIT_RELATION_INCOMPLETE 아님
3. NUMBER_HOLD·NUMBER_FAIL 조건 아님
4. 대표 문맥 존재
5. primary 전체 표본 20건 이상
6. primary 최근100 표본 8건 이상
7. primary 통합 전체가 NEGATIVE_CONFIRMED가 아님
8. primary 본번호 전체가 NEGATIVE_CONFIRMED가 아님
9. number_opposite_risk != HIGH
10. number_bonus_dependence != HIGH
11. number_structure_state != SEVERE
12. number_context_conflict != HIGH

PARETO_DOMINATED TEST는 유효할 수 있으나
비지배 TEST보다 뒤에 둔다.

---

# 13. NUMBER_RETIRED

정상 매회 1~45 분석에서는 사용하지 않는다.

다음 경우의 과거 장부 행에만 사용한다.

- 새 규칙 버전으로 대체된 번호 판정 행
- 폐기된 탐색가족의 과거 후보
- 승인 취소된 실험 예외판의 과거 후보

RETIRED 행은 삭제하지 않으며
현재 후보군에는 들어가지 않는다.
`retired_reason`과 대체 버전 ID를 반드시 저장한다.

# 14. 복귀·비복귀 역할

## 14.1 미래 데이터 차단

분석 대상이 R이면 역할 계산은 R-1까지의 자료만 사용한다.

## 14.2 UNIT별 복귀 역할

번호가 속한 UNIT 그룹에 대해 다음을 계산한다.

- RETURN_FROM_ANNIHILATION:
  R-1 점유가 0
- RETURN_FROM_LOW_OCCUPANCY:
  R-1 점유가 해당 그룹의
  R-2까지 과거 점유 분포 25백분위 이하
- CONTINUATION_CONTEXT:
  위 두 조건이 아님

미래의 실제 복귀 깊이 1·2를 미리 사용하지 않는다.
복귀 깊이는 사후 복기에만 사용한다.

## 14.3 공식 복귀 후보

다음 모두를 만족하면 공식 복귀 후보다.

1. 하나 이상의 UNIT에서 RETURN 역할 존재
2. NUMBER_PASS·NUMBER_WEAKEN·유효 NUMBER_TEST 중 하나
3. NUMBER_HOLD·NUMBER_FAIL 아님
4. 역할 계산 미래 데이터 차단 완료

여러 UNIT의 복귀 역할을 모두 `return_roles_json`에 저장한다.

## 14.4 주 역할

표시용 주 역할은 다음 순서로 선택한다.

1. RETURN_FROM_ANNIHILATION
2. RETURN_FROM_LOW_OCCUPANCY
3. CONTINUATION_CONTEXT
4. 구조 위험이 낮은 역할
5. 대표 문맥과 같은 UNIT 역할
6. 그래도 같으면 UNIT 저장 순서

주 역할은 다른 역할을 삭제하지 않는다.

## 14.5 비복귀 역할

공식 복귀 후보가 아니며
NUMBER_PASS·NUMBER_WEAKEN·유효 NUMBER_TEST이면
`NONRETURN_CANDIDATE`다.

---

# 15. 역할 중복

번호별 역할 서명:

```text
role_signature
= set(
  unit_type,
  role_type,
  group_id,
  evidence_key
)
```

두 번호의 중복 상태:

- IDENTICAL: 서명이 완전히 같음
- HIGH: 주 역할 튜플이 같음
- PARTIAL: 교집합이 하나 이상
- NONE: 교집합 없음

후보별 `overlap_profile`은
다른 유효 후보들과의 다음 개수를 저장한다.

```text
(
  identical_count,
  high_count,
  partial_count
)
```

합산점수를 만들지 않는다.
동점 단계에서는 위 튜플을 오름차순 사전식으로 비교한다.

---

# 16. 번호 동점 순서의 정확한 비교키

다음 순서를 사전식으로 비교한다.

1. NUMBER 상태:
   PASS > WEAKEN > TEST
2. 다섯 UNIT COMPLETE:
   TRUE > FALSE
3. 파레토:
   NONDOMINATED > DOMINATED > NOT_COMPARABLE
4. 관계:
   CONSENSUS > PARTIAL > CONFLICT_NO_HIGH > NO_SUPPORT
5. primary 통합 전체 Wilson 하한: 높은 값
6. 기간 유지 튜플:
   전체 증거 라벨,
   최근100 증거 라벨,
   최근50 증거 라벨,
   최근100 관측률,
   최근50 관측률
7. primary 본번호 Wilson 하한: 높은 값
8. 독립 문맥:
   MULTI_INDEPENDENT > SINGLE_INDEPENDENT > NONE
9. 표본:
   SUFFICIENT > BORDERLINE > INSUFFICIENT,
   이후 전체 표본 수 큰 값
10. 구조:
    NORMAL > CAUTION > WARNING > SEVERE
11. 역할 중복:
    overlap_profile 오름차순
12. number_context_conflict:
    NONE > MEDIUM > HIGH
13. number_opposite_risk:
    LOW > MEDIUM > HIGH

# 17. 후보군 압축

## 17.1 PASS 후보가 6개 이상

- 6~12개: 전부 핵심 PASS 후보군
- 13개 이상: 제16장 동점 순서 상위 12개

12개를 채우기 위해 WEAKEN·TEST를 추가하지 않는다.

## 17.2 PASS 후보가 6개 미만

확장 후보군 원본:

```text
모든 NUMBER_PASS
+ 모든 NUMBER_WEAKEN
+ 모든 유효 NUMBER_TEST
```

- PASS는 반드시 전부 포함
- NUMBER_HOLD·NUMBER_FAIL·NUMBER_RETIRED 제외
- 비지배 후보 우선
- 지배 후보는 비지배 후보만으로 6개를 채우지 못할 때만 사용
- 전체 6~12개: 전부 사용
- 13개 이상: 제16장 동점 순서 상위 12개
- 전체 6개 미만: CORE_RESEARCH_HOLD 사유 기록

확장 후보군을 사용한 사실을
`candidate_pool_type = EXPANDED_TEST_POOL`로 저장한다.
이후 최종 CORE 상태의 상한은 CORE_TEST_SET_READY다.

## 17.3 6단계 종료점

6단계에서는 다음만 저장한다.

- 1~45 NUMBER 상태
- 복귀·비복귀 역할
- 파레토·관계
- 최초 실패·제한 관문
- 동점 키와 최종 번호 순위
- 후보군 유형과 최대 12개 후보
- 실행·결정 해시

6단계에서 금지:

- TRIO 생성
- PAIR 생성
- 최종 숫자 6개 확정
- 세트1·세트2 생성
- CORE_SET_READY 확정
- 잠금 결과 생성
- 웹화면 변경
- 감사 실행
- LIVE_OFFICIAL 적용
