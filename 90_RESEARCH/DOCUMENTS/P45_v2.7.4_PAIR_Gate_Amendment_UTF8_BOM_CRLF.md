# 1. PAIR 기본 객체와 canonical key

## 1.1 기본 객체

PAIR 연구 객체는 **unordered pair of TRIOs**로 정의하는 안을 채택한다.

필수 조건:

- 두 constituent 모두 현재 평가회차에서 `valid_for_pair = TRUE`
- 각 TRIO는 `(n1,n2,n3)`, `n1 < n2 < n3`
- 두 TRIO의 번호 교집합이 공집합
- 합집합 크기가 정확히 6
- TRIO_RETIRED, valid_for_pair=FALSE, SYSTEM_ERROR는 입력 금지

PAIR 생성 입력 순서는 연구 의미를 갖지 않는다. SET1/SET2는 제15장의 별도 출력 규칙으로 배정한다.

## 1.2 canonical trio key

```text
trio_key = decimal(n1) + "-" + decimal(n2) + "-" + decimal(n3)
```

숫자에는 선행 0을 사용하지 않는다.

## 1.3 canonical pair key

두 `trio_key`를 UTF-8 코드포인트 기준 사전식 오름차순으로 정렬한다.

```text
lower_trio_key = min_lex(trio_key_A, trio_key_B)
upper_trio_key = max_lex(trio_key_A, trio_key_B)
canonical_pair_key = lower_trio_key + "__" + upper_trio_key
```

예:

```text
2-13-27__31-39-45
```

A/B 입력 순서를 바꾸어도 같은 key가 나와야 한다. DB unique key는 `(pair_run_id, canonical_pair_key)`다.

# 2. PAIR outcome taxonomy

## 2.1 원자료

각 결과 회차에서 다음을 별도로 저장한다.

- `a_integrated_hits`, `b_integrated_hits`: 각각 0..3
- `a_main_hits`, `b_main_hits`: 각각 0..3
- `a_bonus_assisted_triple`, `b_bonus_assisted_triple`: boolean
- `integrated_outcome_category`
- `main_outcome_category`

성과 원자료는 category에 의해 삭제·축약되지 않는다.

## 2.2 상호배타적 category 함수

아래 함수 `category(x,y)`를 integrated와 main에 각각 독립 적용한다.

1. `x=3 AND y=3` → `DOUBLE_TRIPLE_SUCCESS`
2. `(x=3) XOR (y=3)` → `SINGLE_TRIPLE_SUCCESS`
3. `x!=3 AND y!=3 AND x=2 AND y=2` → `NO_TRIPLE_WITH_DOUBLE_EXACT2`
4. `x!=3 AND y!=3 AND ((x=2) XOR (y=2))` → `NO_TRIPLE_WITH_SINGLE_EXACT2`
5. 그 외 → `NO_TRIPLE_NO_EXACT2`

우선순위 1→5를 적용하므로 16가지 `(x,y)`가 정확히 한 category에 들어간다. `3+2`는 `SINGLE_TRIPLE_SUCCESS`이며 다른 member의 exact2 원자료는 보존하되 PRIMARY와 합산하지 않는다.

## 2.3 공식 사건

- PRIMARY: `AT_LEAST_ONE_TRIPLE_SUCCESS = (x=3 OR y=3)`
- DOUBLE PRIMARY: `(x=3 AND y=3)`
- SUPPORT: `NO_TRIPLE_EXACT2_SUPPORT = (x<3 AND y<3 AND (x=2 OR y=2))`
- DOUBLE SUPPORT: `(x=2 AND y=2)`
- SIMULTANEOUS FAILURE: `(x<2 AND y<2)`

PRIMARY와 SUPPORT의 성공 수·노출 수·통계검정은 별도 열과 별도 레코드로 저장하고 합산하지 않는다.

# 3. PAIR exact random baseline

## 3.1 변수와 표본공간

- 전체 번호 수 `N=45`
- 서로 겹치지 않는 고정 TRIO A와 B, 각 크기 3
- 당첨집합 크기 `m`; integrated는 `m=7`, main은 `m=6`
- `a=|A∩D|`, `b=|B∩D|`
- 나머지 번호 수 `39`
- 표본공간 `C(45,m)`

정확한 `(a,b)` 경우의 수:

```text
W_m(a,b) = C(3,a) C(3,b) C(39,m-a-b)
P_m(a,b) = W_m(a,b) / C(45,m)
```

범위 밖 조합수는 0이다. 모든 baseline은 16개 `(a,b)` 셀의 유한 합으로도 검산한다.

## 3.2 PRIMARY

```text
P_m(at least one 3/3)
= [2 C(42,m-3) - C(39,m-6)] / C(45,m)

P_m(double 3/3)
= C(39,m-6) / C(45,m)
```

교집합을 정확히 빼므로 두 TRIO를 독립으로 가정하거나 단일 확률에 단순히 2를 곱하지 않는다.

## 3.3 exact2 SUPPORT — 3/3 제외

```text
P_m(double exact2, no triple)
= C(3,2)^2 C(39,m-4) / C(45,m)

P_m(single exact2, no triple)
= [2 C(3,2) Σ_{b∈{0,1}} C(3,b)C(39,m-2-b)] / C(45,m)

P_m(no-triple exact2 support)
= 위 두 확률의 합
```

## 3.4 검산 고정값

Integrated `m=7`:

- sample space: 45,379,620
- at least one triple: 223,821 / 45,379,620 = 0.004932192028051359
- double triple: 39 / 45,379,620
- double exact2 no triple: 82,251 / 45,379,620
- single exact2 no triple: 4,935,060 / 45,379,620
- no-triple exact2 support: 5,017,311 / 45,379,620 = 0.11056308977466096

Main `m=6`:

- sample space: 8,145,060
- at least one triple: 22,959 / 8,145,060 = 0.0028187637660127733
- double triple: 1 / 8,145,060
- double exact2 no triple: 6,669 / 8,145,060
- single exact2 no triple: 658,008 / 8,145,060
- no-triple exact2 support: 664,677 / 8,145,060 = 0.08160492372063557

`draft_validation/pair_baseline_enumeration.py`의 closed form과 16셀 finite enumeration이 두 m에서 모두 일치해야 한다.

# 4. 별도 PAIR walkforward

Stage 7.2 집계를 조합해 PAIR 과거성과를 만들지 않는다. 원본 historical draw data에서 각 R마다 전체 파이프라인을 다시 실행한다.

평가회차 R 순서:

1. 1..R-1 draw만 로드하고 `data_prefix_hash` 고정
2. UNIT_3·5·9·10·END_DIGIT 재계산
3. UNIT state와 relation 재계산
4. NUMBER state와 당시 candidate pool 재계산
5. 당시 모든 TRIO와 TRIO state 재계산
6. 당시 `valid_for_pair` 재판정
7. 모든 disjoint PAIR 생성
8. pair coverage·risk·structure context·signature 계산
9. state와 Pareto 계산
10. 제14장의 공개 15-key로 사전 rank
11. 결과를 읽기 전에 prediction과 hash를 원자적으로 저장
12. R 결과로 outcome 복기

회차 하나가 하나의 transaction이다. COMPLETE 전에는 공식 exposure 집계에 포함하지 않는다.

필수 상태:

- PENDING, RUNNING, COMPLETE
- SKIPPED_TRIO_UNDER_2
- SKIPPED_NO_DISJOINT_PAIR
- SKIPPED_RESEARCH_HOLD
- FAILED_RETRYABLE, FAILED_FATAL

최초 eligible round는 고정 숫자로 만들지 않는다. 위 파이프라인에서 최초로 `valid_for_pair` TRIO 2개 이상과 disjoint PAIR 1개 이상이 결과 전에 생성된 최초 R이다.

# 5. PAIR exposure

## 5.1 selection rule exposure

각 외부 회차 R과 각 `pair_rule_signature`에서 결과 전 15-key rank가 가장 높은 대표 PAIR **최대 1개**만 `pair_selection_rule_exposure`로 기록한다.

unique constraint:

```text
(walkforward_run_id, evaluation_round, pair_rule_signature)
```

동일 signature 후보가 여러 개면 제14장 rank 후 canonical pair key 오름차순으로 하나를 고른다. 결과를 본 뒤 대표를 교체하지 않는다.

## 5.2 identity exposure

각 회차에 후보로 실제 생성된 모든 canonical PAIR identity를 별도 기록한다.

unique constraint:

```text
(walkforward_run_id, evaluation_round, canonical_pair_key)
```

identity exposure는 후보 등장 횟수이며 공식 rule 성과 분모가 아니다. rule 성과 분모는 대표 selection exposure만 사용한다. 이렇게 분리하여 한 회차의 다수 후보를 독립 표본처럼 중복 계산하는 selection bias를 차단한다.

## 5.3 표본 band

`PAIR_INHERITS_TRIO_SAMPLE_BANDS`:

- `>=200`: READY 통계 관문 평가 가능
- `50..199`: 최대 PAIR_TEST_READY
- `<50`: PAIR_RESEARCH_HOLD

결과에 따라 band를 변경하지 않는다.

# 6. pair_rule_signature

## 6.1 버전

```text
signature_version = PAIR-RULE-SIGNATURE-1.0
```

## 6.2 입력 payload

- pair pool type
- 두 constituent TRIO state의 정렬 vector
- 두 `trio_rule_signature`의 사전식 정렬 vector
- 다섯 UNIT별 pair coverage relation vector
- role diversity vector
- evidence overlap vector
- member maximum risk
- pair rule opposite risk
- final structure context
- recent support state
- bonus dependence state

제외:

- 숫자 identity와 canonical pair key
- outcome count/rate·p-value·Wilson
- 평가회차 실제 결과
- 미래 자료
- final rank

## 6.3 직렬화

JSON object key는 Unicode 코드포인트 오름차순, 배열 순서는 명시된 canonical 순서, 공백 없음, UTF-8, 숫자는 JSON 표준 10진 표현, NaN/Infinity 금지다.

```text
pair_rule_signature = SHA-256(canonical_utf8_json(payload))
```

두 TRIO 관련 배열은 canonical trio key가 아니라 해당 구조값 자체를 사전식 정렬하므로 member 입력 순서에 영향을 받지 않는다.

# 7. PAIR_UNIT_COVERAGE_MATRIX

두 TRIO의 기존 `3×5 trio_unit_coverage_matrix` 원본을 그대로 보존한다.

PAIR matrix shape:

```text
member axis: [canonical_lower_member, canonical_upper_member]
number axis: [member n1, n2, n3]
unit axis: [UNIT_3, UNIT_5, UNIT_9, UNIT_10, END_DIGIT]
shape: 2 × 3 × 5 = 30 raw cells
```

각 raw cell은 TRIO 원본의 unit state, support relation, role, evidence IDs, conflict flag를 그대로 가진다.

PAIR별 UNIT relation cell은 다음 원자료만 저장한다.

- member state pair
- complete cell count 0..6
- support cell count 0..6
- conflict cell count 0..6
- distinct role count
- shared evidence ID count

평균·점수는 생성하지 않는다.

- `PAIR_UNIT_COMPLETE`: 30개 raw cell 모두 COMPLETE
- `PAIR_UNIT_INCOMPLETE`: 하나 이상 누락/오류
- pair unit conflict count: conflict flag가 있는 다섯 UNIT 열의 수 0..5

role diversity vector는 UNIT 순서별 `distinct_role_count`이며 클수록 구조 파레토에서 우수하다. evidence overlap vector는 UNIT 순서별 `shared_evidence_id_count`이며 작을수록 우수하다.

# 8. PAIR risk

위험 순서: `LOW < MEDIUM < HIGH`; SYSTEM_ERROR는 위험값이 아니라 시스템 경로다.

## 8.1 member risk

`member_trio_opposite_risk = max(A risk, B risk)`를 보수적 상한으로 사용한다. 평균하지 않는다.

## 8.2 pair rule risk

HIGH — 하나라도 참:

1. PAIR PRIMARY = INFERIOR_CONFIRMED
2. PRIMARY 양성 주장과 PAIR SUPPORT INFERIOR_CONFIRMED 동시 존재
3. PAIR BONUS_DEPENDENCE_HIGH
4. RECENT_SUPPORT_COLLAPSE_SEVERE
5. pair UNIT conflict 열 2개 이상
6. main PRIMARY INFERIOR_CONFIRMED이면서 integrated PRIMARY SUPERIOR_CONFIRMED

MEDIUM — HIGH가 아니고 하나라도 참:

1. member risk 최대 MEDIUM
2. PRIMARY 양성이나 SUPPORT INFERIOR_TENTATIVE
3. BONUS_DEPENDENCE_MEDIUM
4. recent WARNING
5. pair UNIT conflict 열 1개

그 외 LOW.

## 8.3 final risk

```text
final_pair_opposite_risk = max(member_trio_opposite_risk, pair_rule_opposite_risk)
```

이는 보수적 상한이며 평균·가중치가 아니다.

# 9. PAIR structure collapse

member 구조와 PAIR rule 구조를 분리한다.

PAIR 대표 selection exposure 시계열에서 다음 adverse metrics를 계산한다.

1. `max(0, overall primary rate - recent100 primary rate)`
2. `max(0, overall primary rate - recent50 primary rate)`
3. `max(0, overall support rate - recent100 support rate)`
4. `max(0, overall support rate - recent50 support rate)`
5. `max(0, recent50 simultaneous-failure rate - overall simultaneous-failure rate)`
6. `max(0, recent50 pair-unit-conflict exposure rate - overall rate)`

각 과거 적격 종점에서 같은 지표를 계산해 empirical distribution을 만든다. 현재 값 이하인 과거 값의 비율을 백분위로 사용하고, 최종 percentile은 여섯 percentile의 최대값이다.

- `<90`: NORMAL
- `90<=p<95`: CAUTION
- `95<=p<99`: WARNING
- `>=99`: SEVERE
- 과거 비교 종점 `<50`: INSUFFICIENT_SAMPLE

임계값은 TRIO v2.7.3을 그대로 상속한다. 입력 누락·계산 실패는 SYSTEM_ERROR이며 INSUFFICIENT_SAMPLE로 숨기지 않는다.

member structure summary는 두 TRIO의 더 나쁜 실제 상태다. final PAIR structure는 member summary와 pair rule structure 중 더 나쁜 실제 상태다. INSUFFICIENT_SAMPLE은 별도 flag로 보존한다.

# 10. recent support·통계·bonus dependence

## 10.1 창

OVERALL, RECENT_100, RECENT_50, RECENT_20은 달력 회차가 아니라 해당 signature의 대표 `pair_selection_rule_exposure` 순서다.

## 10.2 recent exact2

PAIR SUPPORT baseline `P_PAIR_INT_EXACT2_NO_TRIPLE`을 사용해 TRIO v2.7.3 규칙을 그대로 상속한다.

SEVERE:

- recent100·recent50 둘 다 존재
- 두 창 관측률 모두 baseline 미만
- 두 창 Wilson upper 모두 `max(baseline, overall Wilson lower)` 미만

WARNING: 위 창 조건을 하나만 만족. 그 외 STABLE. RECENT_20은 TEST_ONLY 진단이며 단독 상태 결정 금지다.

## 10.3 통계검정

PRIMARY와 SUPPORT 각각 별도:

- Wilson 95%
- upper one-sided exact binomial
- lower one-sided exact binomial
- alpha 0.05
- 귀무확률은 제3장의 해당 exact PAIR baseline

TRIO v2.7.3의 SUPERIOR_CONFIRMED/TENTATIVE/NEUTRAL/INFERIOR_TENTATIVE/CONFIRMED 비교식을 상속한다. PRIMARY와 SUPPORT를 합산하지 않는다.

## 10.4 bonus dependence

integrated PRIMARY 노출을 다음으로 분리한다.

- MAIN_PRIMARY: 적어도 한 TRIO가 main 3/3
- BONUS_ASSISTED_PRIMARY: integrated PRIMARY이며 main PRIMARY가 아님

HIGH: integrated PRIMARY SUPERIOR_CONFIRMED AND main PRIMARY INFERIOR_CONFIRMED.

MEDIUM: integrated PRIMARY 방향 양성 AND main PRIMARY 관측률이 main baseline 미만 AND main 열위 확정은 아님.

그 외 NONE. TRIO v2.7.3 경계를 그대로 상속한다.

# 11. PAIR 상태 precedence

한 PAIR에는 다음 우선순위를 위에서 아래로 한 번 적용한다.

```text
PAIR_SYSTEM_HOLD
→ PAIR_RESEARCH_HOLD
→ PAIR_READY
→ PAIR_TEST_READY
```

## 11.1 PAIR_SYSTEM_HOLD

하나라도 참:

- 필수 UNIT/NUMBER/TRIO 입력 누락 또는 SYSTEM_ERROR
- PAIR_UNIT_INCOMPLETE
- 미래누출 검사 FAIL
- prediction hash 결과 전 저장 FAIL
- 동일 입력 10회 불일치
- 관문 순서 불일치
- 필수 장부 원자 저장 실패
- signature 생성 실패

## 11.2 PAIR_RESEARCH_HOLD

SYSTEM_HOLD가 아니고 하나라도 참:

- valid TRIO 2개 미만
- 현재 pair가 비중복 조건 위반
- selection exposure `<50`
- final opposite risk HIGH
- final structure SEVERE
- BONUS_DEPENDENCE_HIGH
- PRIMARY 또는 SUPPORT INFERIOR_CONFIRMED
- recent support SEVERE
- pair UNIT conflict 열 2개 이상

## 11.3 PAIR_READY

SYSTEM/RESEARCH HOLD가 아니며 제12장 14개 gate가 모두 PASS일 때만 READY.

## 11.4 PAIR_TEST_READY

앞 상태가 아니고 다음을 모두 만족:

1. 두 member 모두 `valid_for_pair=TRUE`
2. member 상태는 PASS·WEAKEN·유효 TEST만 허용
3. 다음 A 또는 B 중 하나:
   - A. 하나 이상이 WEAKEN/TEST이거나 pool이 EXPANDED_TEST_POOL이거나 exposure가 50..199
   - B. 제11.4.1항의 `BASELINE_ONLY_READY_GATE_FAIL` 조건을 모두 만족
4. exposure `>=50`
5. PRIMARY·SUPPORT 모두 INFERIOR_CONFIRMED 아님
6. final risk != HIGH
7. final structure != SEVERE
8. BONUS_DEPENDENCE_HIGH 아님
9. recent != SEVERE
10. pair UNIT conflict 열 `<2`
11. 미래누출·결정론·signature·prediction hash·저장 PASS

WARNING, MEDIUM, INSUFFICIENT_SAMPLE 또는 RECENT20 TEST_ONLY는 READY를 금지하되 위 조건을 만족하면 TEST_READY를 허용한다. 기준을 완화해 READY로 승격하지 않는다.

현재처럼 TRIO_PASS=0이면 PAIR_READY=0이다. valid TEST 12개라는 이유만으로 실제 PAIR_TEST_READY가 자동 생성되는 것은 아니며, 모든 PAIR 관문과 순차검증을 통과해야 한다.

### 11.4.1 BASELINE_ONLY_READY_GATE_FAIL

PAIR_READY 14개 gate 중 `FAIL`인 gate ID의 집합을 `F`로 정의한다. `INCOMPLETE`는 FAIL에 합치지 않고 PAIR_SYSTEM_HOLD로 처리한다.

다음을 모두 만족할 때만 `BASELINE_ONLY_READY_GATE_FAIL = TRUE`다.

1. 두 constituent가 모두 TRIO_PASS
2. pair selection exposure >= 200
3. `F != empty`
4. `F`가 `{PG07, PG08}`의 부분집합
5. PG07·PG08 관련 PRIMARY evidence 중 `INFERIOR_CONFIRMED` 없음
6. PAIR_SYSTEM_HOLD 조건 없음
7. PAIR_RESEARCH_HOLD를 강제하는 다른 조건 없음

PG07·PG08 외 gate가 하나라도 FAIL이면 이 경로를 적용하지 않는다. 이 경로는 PAIR_READY의 14-gate 전부 PASS 조건을 변경하지 않으며, PAIR_READY 승격이 아니라 PAIR_TEST_READY 연구경로다. 기존 상태 precedence를 그대로 적용하므로 SYSTEM_HOLD 또는 RESEARCH_HOLD 조건이 동시에 존재하면 해당 HOLD가 우선한다.

# 12. PAIR_READY 14 gates 완결화

모든 gate는 PASS/FAIL/INCOMPLETE와 원자료를 독립 저장한다. INCOMPLETE는 필수 입력 누락일 때만 사용한다.

| Gate | exact predicate | required data | failure code |
|---|---|---|---|
| PG01 | member A,B state 모두 TRIO_PASS | TRIO ledger | PAIR_MEMBER_NOT_BOTH_PASS |
| PG02 | member number intersection empty AND union size=6 | trio numbers | PAIR_OVERLAP |
| PG03 | 다섯 UNIT 계산 status 모두 COMPLETE | UNIT ledger | MANDATORY_UNIT_INCOMPLETE |
| PG04 | 30 coverage cells 모두 COMPLETE | pair coverage | PAIR_COVERAGE_INCOMPLETE |
| PG05 | 모든 R 입력 end=R-1, prediction hash가 결과 read 전에 존재 | WF round | LEAKAGE_OR_PRELOCK_FAIL |
| PG06 | pair_selection_rule_exposure_count >=200 | exposure ledger | PAIR_SAMPLE_UNDER_200 |
| PG07 | integrated PRIMARY observed rate > exact baseline AND INFERIOR_CONFIRMED 아님 | primary stat | PAIR_PRIMARY_BASELINE_FAIL |
| PG08 | main PRIMARY observed rate >= exact main baseline AND INFERIOR_CONFIRMED 아님 | main stat | PAIR_MAIN_BASELINE_FAIL |
| PG09 | recent support state != SEVERE | period metric | PAIR_RECENT_COLLAPSE |
| PG10 | final_pair_opposite_risk != HIGH | risk ledger | PAIR_OPPOSITE_HIGH |
| PG11 | final structure != SEVERE | structure ledger | PAIR_STRUCTURE_SEVERE |
| PG12 | 동일 canonical input 10회 decision/execution/rank hash가 하나 | determinism record | PAIR_DETERMINISM_FAIL |
| PG13 | expected gate IDs PG01..PG14와 executed sequence가 동일하고 숨은 gate 0 | gate ledger | PAIR_GATE_SEQUENCE_FAIL |
| PG14 | 필수 normalized rows·report·hash 저장 완료 및 FK/integrity PASS | DB/report | PAIR_LEDGER_INCOMPLETE |

PG13은 자기 자신을 포함한 실행순서를 인증하되 PG14 저장 결과는 transaction commit 직전 staged 검증으로 기록하고 commit 성공 후 최종 PASS로 확정한다. 하나라도 FAIL이면 READY가 아니다.

# 13. Structural Pareto

PAIR 상태와 Pareto는 분리한다. Pareto는 상태를 승격하지 않는다.

정확한 structural vector:

1. pair UNIT conflict 열 수 — 낮을수록 우수
2. incomplete raw cell 수 — 낮을수록 우수
3. UNIT 순서별 distinct role count 5-vector — 각 원소 높을수록 우수
4. UNIT 순서별 shared evidence ID count 5-vector — 각 원소 낮을수록 우수
5. member risk ordinal — 낮을수록 우수
6. pair rule risk ordinal — 낮을수록 우수
7. final structure ordinal — 낮을수록 우수

A가 B보다 모든 차원에서 나쁘지 않고 최소 한 차원에서 엄격히 우수할 때만 DOMINATE한다. 방향이 갈리면 둘 다 NONDOMINATED다. 성과율·p-value·Wilson·숫자 identity는 structural Pareto에 넣지 않는다.

---

# 14. PAIR ranking 15-key

사전식 비교만 사용한다. NULL은 유리하게 처리하지 않는다: benefit numeric NULL=`-∞`, adverse numeric NULL=`+∞`, category NULL=최악. 필수 NULL은 앞서 SYSTEM_HOLD다.

| 순서 | 기존 개념 | deterministic key | 방향 |
|---:|---|---|---|
| 1 | 둘 다 TRIO_PASS | `both_pass` boolean | DESC |
| 2 | PAIR 파레토 | NONDOMINATED > DOMINATED > NOT_COMPARABLE | DESC |
| 3 | 최소 한 세트 3/3 | integrated PRIMARY observed rate | DESC |
| 4 | 무작위 초과폭 | primary rate - exact integrated baseline | DESC |
| 5 | 본번호 3/3 | main PRIMARY observed rate | DESC |
| 6 | 통합 2/3 지지 | no-triple exact2 support rate | DESC |
| 7 | recent 유지 | STABLE > WARNING > SEVERE > INSUFFICIENT | DESC |
| 8 | 더 약한 member 성과 | 두 member의 `(int3 Wilson low,int3 rate,main3 Wilson low,int2 Wilson low)` 중 사전식 최소 vector | DESC |
| 9 | 충돌 적고 HIGH 없음 | `(final risk!=HIGH, -pair_unit_conflict_count)` | DESC |
| 10 | 반대 위험 | LOW > MEDIUM > HIGH | DESC |
| 11 | 구조 | NORMAL > CAUTION > WARNING > SEVERE > INSUFFICIENT | DESC |
| 12 | 역할·근거 분산 | role diversity 5-vector DESC 후 evidence overlap 5-vector ASC | 혼합 명시 |
| 13 | 동시 실패율 | simultaneous failure observed rate | ASC |
| 14 | SET1 정렬 숫자열 | `(set1_n1,set1_n2,set1_n3)` | ASC |
| 15 | SET2 정렬 숫자열 | `(set2_n1,set2_n2,set2_n3)` | ASC |

15개가 완전히 같으면 `canonical_pair_key` UTF-8 사전식 ASC를 유일한 stable storage key로 사용한다. 이는 숨은 연구 비교키가 아니라 동일 결과의 저장 순서 안정화 키다.

---

# 15. SET1 / SET2

PAIR canonical member 순서와 출력 라벨을 분리한다.

1. 두 member의 공식 TRIO v2.7.3 16-key rank vector를 비교한다.
2. 더 우수한 vector member를 SET1로 배정한다.
3. vector가 완전히 같으면 trio number tuple 오름차순이 빠른 member를 SET1로 배정한다.
4. 다른 member는 SET2다.

결과 확인 후 라벨 교환을 금지한다. SET 배정은 prediction hash 전에 완료한다.

---

# 16. PAIR → CORE 전환

| PAIR 결과 | 추가 필수조건 | CORE 결과 |
|---|---|---|
| PAIR_READY | PG01..PG14 PASS, report/hash PASS, lock transaction 준비 | CORE_SET_READY 가능 |
| PAIR_TEST_READY | TEST 결정표 전부 PASS, report/hash PASS | CORE_TEST_SET_READY 가능 |
| PAIR_RESEARCH_HOLD | 없음 | CORE_RESEARCH_HOLD |
| PAIR_SYSTEM_HOLD | 없음 | CORE_SYSTEM_HOLD |

final six는 선택된 PAIR의 SET1∪SET2로만 생성하며 PAIR 선택 이전에 만들지 않는다. 공식 잠금은 결과 발표 전 prediction hash, DB transaction, report hash, manifest hash가 모두 완료된 뒤 수행한다.

AUDIT NOT_RUN/PENDING/INCOMPLETE는 CORE HOLD 사유가 아니다. 감사 결과는 이미 잠긴 CORE SET을 변경하지 못하며 인증 수준만 변경한다.
